# Продуктовая документация

Здесь описано, **что** делает приложение и **как это выглядит для ученика**. Как это устроено в коде —
[ARCHITECTURE.md](../ARCHITECTURE.md). Методика, юридическая граница и история решений — [PRODUCT.md](../PRODUCT.md).

> Статус: черновик структуры (ноябрь 2026). Разделы с пометкой **план** ещё не реализованы.

## Зачем отдельная папка

Контента будет много: главы, ежедневные задания, ивенты. Пишут его в том числе агенты. Чтобы контент
был качественным и одинаковым по духу, у каждой единицы должна быть спецификация, по которой её можно
написать и проверить, не заглядывая в код:

- **режим** — зачем он ученику, из чего состоит, как устроен прогресс и награды;
- **тип задания** — что видит и делает ученик, как проверяется ответ, что меняется по уровням, где тип допустим;
- **тексты интерфейса** — одни и те же слова для одних и тех же действий во всём приложении.

## Правила документации

1. **Один источник правды.** Факт описан в одном месте, остальные ссылаются. Объяснения грамматики —
   только в справочнике (`/grammar`), правила контента — в [AGENTS.md](../../AGENTS.md), продуктовые — здесь.
2. **Спецификация раньше контента.** Новый тип задания или режим сначала описывается здесь (карточка типа
   в `tasks.md`), потом реализуется, потом наполняется.
3. **Карточка типа задания = контракт.** У каждого типа: id, данные, проверка, уровни, где допустим, тексты.
   Цель — чтобы реестр типов в коде (`план`) повторял эти карточки поле в поле и матрица в документации
   собиралась из него, а не писалась вручную.
4. **Статус у каждого раздела:** готово / черновик / план. «Готово» — описано то, что работает на сайте.
5. **Тексты интерфейса — дословно**, в «ёлочках», как на экране. Новая кнопка — сначала проверить
   словарь в [copy.md](copy.md).

## Конструктор (план)

Страницы режимов (карта, календарь, экран ивента, шаг) — код. Содержимое — **конфиги**: глава, день,
ивент описываются данными из блоков-типов заданий из каталога. Каждый конфиг проверяется схемой и
скриптами (как `pnpm lexicon:check`): матрица уровней, «ответ не виден в тексте», только пройденная грамматика.
Подробности появятся, когда начнём переводить типы на реестр.
